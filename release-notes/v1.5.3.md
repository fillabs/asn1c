# v1.5.3 Release Notes

## Changes since v1.5.2

### Highlights

- Corrected IMPORTS resolution so explicitly imported names come from the
  module named in the `FROM` clause. The `-fprefer-import-source` option
  disables the legacy whole-module fallback.
- Fixed PER extensibility handling for information-object identifier fields
  and component-relation constraints, with UPER and APER regression coverage.
- Corrected UPER/APER CHOICE mapping between declaration order and canonical
  order.
- Prevented generated filenames from colliding with runtime skeleton files on
  case-insensitive filesystems.

### Notable fixes and improvements

- Diagnosed repeated module references in `IMPORTS` and avoided false
  duplicate-OID reports when identifiers use name-form arcs.
- Removed spurious diagnostics when looking up parameterized imported types
  and ensured every `FATAL` diagnostic results in a non-zero compiler exit
  status.
- Fixed a parallel skeleton uninstall race that could make `make distcheck`
  fail.
- Made `asn1p_constr.h` self-contained and moved constraint enums to file
  scope for improved C++ code-analyzer compatibility.
- Updated the usage guide and man page, including the transfer-syntax API
  table and its groff rendering.
